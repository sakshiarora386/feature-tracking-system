## 2. Findings by Severity

### High Severity

#### 1. **Correctness: Improper Side Effect in Render Body**
- **File:** [`feature-request-tracker/components/organisms/FeatureRequestForm.tsx:26`](feature-request-tracker/components/organisms/FeatureRequestForm.tsx:26)
- **Dimension:** Correctness
- **Issue:** The `router.push('/')` call is placed directly in the component's render body. This is a side effect that should not occur during rendering. It can lead to unexpected navigation, multiple re-renders, and errors in future versions of React.
- **Fix:** Wrap the navigation logic in a `useEffect` hook that executes only when the `isSuccess` state changes.

```tsx
// SAARTHI-202510221920: HIGH | Correctness
// ISSUE: Side effect (navigation) is performed directly in the render body.
// POLICY: React components should have no side effects during rendering.
// FIX: Move the navigation logic into a `useEffect` hook triggered by `isSuccess`.

// Before
if (isSuccess) {
  router.push('/');
}

// After
import React, { useState, useEffect } from 'react';

useEffect(() => {
  if (isSuccess) {
    router.push('/');
  }
}, [isSuccess, router]);
```

#### 2. **Correctness: Unsafe Type Assertions in Filter Logic**
- **File:** [`feature-request-tracker/components/organisms/FeatureRequestList.tsx:43`](feature-request-tracker/components/organisms/FeatureRequestList.tsx:43)
- **Dimension:** Correctness
- **Issue:** The `onChange` handlers for the filter dropdowns use unsafe type assertions (`as GetFeatureRequestsApiArg['status']`). If the `e.target.value` is an empty string (for "All"), it is cast to `undefined`, but if an unexpected value were ever introduced, it would be cast incorrectly, potentially causing runtime errors or invalid API requests.
- **Fix:** Create a dedicated handler function that validates the value before setting the state. This ensures that only valid enum values or `undefined` are passed to the query hook.

```tsx
// SAARTHI-202510221920: HIGH | Correctness
// ISSUE: Unsafe type assertion on select change can lead to runtime errors.
// POLICY: Avoid unsafe type assertions; validate data at the boundaries.
// FIX: Use a handler function to validate the input before setting state.

// Before
onChange={(e) => setStatus(e.target.value as GetFeatureRequestsApiArg['status'] || undefined)}

// After
const handleStatusChange = (e: React.ChangeEvent<HTMLSelectElement>) => {
  const value = e.target.value;
  if (value === '') {
    setStatus(undefined);
  } else {
    setStatus(value as GetFeatureRequestsApiArg['status']);
  }
};

<Select onChange={handleStatusChange} />
```

#### 3. **Correctness: Use of Blocking `window.confirm`**
- **File:** [`feature-request-tracker/components/organisms/FeatureRequestDetail.tsx:32`](feature-request-tracker/components/organisms/FeatureRequestDetail.tsx:32)
- **Dimension:** Correctness
- **Issue:** The use of `window.confirm` is a synchronous, blocking operation that freezes the UI. This provides a poor user experience and is generally discouraged in modern, dynamic web applications.
- **Fix:** Replace the `window.confirm` with a state-driven modal component. This provides a non-blocking, more professional user experience and allows for greater control over the confirmation flow.

#### 3. **Code Quality: Unsafe Non-Null Assertions**
- **File:** [`feature-request-tracker/components/organisms/FeatureRequestList.tsx:65`](feature-request-tracker/components/organisms/FeatureRequestList.tsx:65)
- **Dimension:** Code Quality
- **Issue:** The non-null assertion operator (`!`) is used on properties like `request.id!`, `request.status!`, etc. This bypasses TypeScript's type safety and can lead to runtime errors if the API ever returns an object without these properties.
- **Fix:** Add checks to ensure the data exists before rendering, or provide fallback values.

#### 4. **Code Quality: Redundant URL Parameter Encoding**
- **File:** [`feature-request-tracker/services/featureRequestApi.ts:27`](feature-request-tracker/services/featureRequestApi.ts:27)
- **Dimension:** Code Quality
- **Issue:** Query parameters in the `getFeatureRequests` endpoint are manually encoded using `encodeURIComponent`. RTK Query's `fetchBaseQuery` handles this automatically. This manual step is redundant and adds unnecessary code.
- **Fix:** Remove the manual `encodeURIComponent` calls and pass the parameters directly.

#### 5. **Correctness: Insufficient Validation in Change Handler**

- **Fix:** Add a check to ensure the selected value is a valid status before calling the `updateStatus` mutation.
